# Auth gate + jack-in UX — 26-10-2026

## Gate (cliente)

`AuthGate` em `Providers` roda após mount: sem `access_token` em `localStorage`, `window.location.replace('/login?next=…')` (full load) para qualquer rota que não esteja na allowlist. Enquanto verifica ou redireciona, mostra shell de loading (sem conteúdo privado).

### Allowlist (sem token)

| Rota | Notas |
|------|--------|
| `/login` | Jack-in |
| `/register` | Criar player (`POST /api/players`) |
| `/_next/*`, assets estáticos | Fora do App Router — não passam pelo gate |

Tudo o mais (`/`, `/campaigns`, `/table`, `/sheet`, etc.) exige login.

### `?next=`

- Definido pelo gate com path + query atual (encoded).
- Após login OK: `window.location.assign(next)` (full load) + `sanitizeAuthNext` evita open redirect e loops em `/login` / `/register`; fallback `/campaigns`.

## CSS / PWA (26-10-2026 fix)

O `sw.js` v3 **não intercepta** `/_next/*`, navegação documento, nem pedidos RSC (`RSC: 1`, `text/x-component`). Cache-first no SW v2 quebrava injeção de CSS modules após `router.push` pós-login (conteúdo sem estilo até F5). Auth usa hard navigation; SW deixa chunks Next sempre na rede.
- Registro bem-sucedido → `/login?next=…` preservando o mesmo destino.

## Telas `/login` e `/register`

- HUD Night City (grid, scanlines, cantos, glitch leve no título com `data-motion=on`).
- Email/senha, mostrar/ocultar senha, validação inline PT, toast de erro, estados loading/disabled.
- Registro: nome, confirmação de senha, hint de força da senha.

## API

- Login: `POST /api/auth/login` → `access_token` + evento `nc-auth-changed`.
- Registro: `POST /api/players` (name, email, password).
